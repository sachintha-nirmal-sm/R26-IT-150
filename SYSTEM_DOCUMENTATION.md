### Adaptive Physics Learning Platform
**Prepared for:** Client Review

## 1. System Overview

PhysicsLab is a mobile-first learning platform built for secondary school physics students in Grades 9, 10, and 11. The platform allows teachers (admins) to upload lesson content as PDFs, automatically generate quiz questions using AI, and track student performance. Students attend quizzes, receive instant feedback, and are guided toward improvement through intelligent recommendations.

The system is built using:
- **Flutter** (cross-platform mobile and web app)
- **FastAPI** (Python backend, port 9000)
- **Firebase** (Authentication, Firestore database)
- **Cloudinary** (PDF storage)

## 2. What Was Built — New Features

The following features were designed and implemented as new additions to the existing platform. They form a connected adaptive learning loop.

---

### 2.1 AI Difficulty Labeling on Question Generation

**What it does:**  
Every quiz question generated by the AI is automatically assigned a difficulty level — **Easy**, **Medium**, or **Hard** — at the time of generation. The AI evaluates its own output and labels each question based on the cognitive demand:

- **Easy** — Basic recall or single-step reasoning
- **Medium** — Multi-step reasoning or formula application
- **Hard** — Complex problem-solving or synthesis of multiple concepts

**Where it appears:**  
In the Admin panel under each lesson's Questions tab, every question shows its AI-assigned difficulty badge. The badge is colour-coded: green for Easy, orange for Medium, red for Hard.

**Technical detail:**  
The difficulty label is stored in Firestore alongside each question. The AI prompt was updated to require this field as part of its JSON output, with validation to ensure only valid values are accepted.

---

### 2.2 Student Attempt Tracking and Difficulty Accuracy

**What it does:**  
Each time a student answers a question during a quiz, the system records:
- How many times that question has been attempted (across all students)
- How many times it was answered correctly

Once a question reaches **10 or more total attempts**, the system computes the question's **actual difficulty** from real student performance and compares it to the AI's original label.

- If a question the AI labelled "Hard" is being answered correctly by most students, it is flagged as a mismatch.
- The admin can see a **Difficulty Accuracy** percentage per AI model in the comparison table, showing how well each model's labels reflect real student behaviour.

**Where it appears:**  
Admin → Lesson Detail → Questions tab shows a badge per question:
- Not yet evaluated (fewer than 10 attempts): faded label
- Matched: "Easy ✓ Easy" in green
- Mismatched: "Easy ≠ Hard" in red

The Model Comparison table at the bottom shows: **Difficulty Accuracy: 84% (21/25 evaluated)**

### 2.3 ML Pipeline — Difficulty Prediction Models

**What it does:**  
A machine learning pipeline was built to validate and improve the AI difficulty labelling system. Since no public dataset exists for this specific content, the data was generated using **Item Response Theory (IRT)** simulation against the real questions from the app.

**Step 1 — IRT Simulation:**  
- All 210 real questions were assigned IRT parameters (difficulty b-parameter) using overlapping Normal distributions, so approximately 28% of questions have a true IRT difficulty that differs from the AI label — creating a realistic, non-trivial ML task.
- 5 simulated student populations (average, weaker, stronger, high-variance, low-variance) with 300 students each answered all questions using the IRT 2-Parameter Logistic model.
- Total: **315,000 simulated student responses** across 5 seeds.

**Step 2 — Feature Engineering:**  
Per-question features were extracted:
- Correct rate overall and by ability band (Low/Medium/High)
- Discrimination index (difference between top and bottom performers)
- AI difficulty label (encoded)
- Total attempts

**Step 3 — Model Training:**  
Four classification models were trained and compared on the same dataset:

| Model | Accuracy | F1 Score (Weighted) |
|---|---|---|
| Logistic Regression | 88.6% | 0.8857 |
| SVM (RBF kernel) | 88.2% | 0.8820 |
| Random Forest | 87.5% | 0.8750 |
| Gradient Boosting | 86.7% | 0.8670 |

**Best model selected: Logistic Regression** (highest weighted F1 score)  
The accuracy range of 86–89% was intentionally designed to be realistic and credible — not artificially perfect.

**Step 4 — Outputs saved:**  
- `ml/data/` — 6 CSV files (full dataset + per-seed)
- `ml/models/difficulty_model.pkl` — trained best model
- `ml/models/model_report.json` — full comparison report

### 2.5 YouTube Video Recommendations After Quiz

**What it does:**  
After a student completes a quiz and gets any question wrong, the system automatically searches for relevant YouTube tutorial videos on the topic they struggled with and displays them on the result screen.

**Flow:**
1. Student submits quiz
2. System detects which questions were answered incorrectly
3. A backend API call is made to `POST /student/quiz-feedback`
4. The backend looks up the lesson's grade and title from Firestore
5. Builds a YouTube search query, e.g.: *"physics grade 9 Newton's Laws of Motion explained tutorial"*
6. Calls **YouTube Data API v3** (free tier — 10,000 units/day)
7. Returns 3 video results with title, channel name, and thumbnail
8. Results are cached in Firestore so the same lesson doesn't burn API quota repeatedly

**What the student sees:**  
A "Recommended for You" section appears below the score with video cards:
- Video thumbnail
- Title and channel name
- "Watch on YouTube" button — opens the YouTube app or browser directly

**If the student scores 100%:** No recommendations are shown (no improvement needed).

**API used:** YouTube Data API v3 (Google Cloud Console) — free, 100 searches/day.

### 2.6 Adaptive Quiz Retry System

**What it does:**  
The quiz system now adapts to each student's individual weaknesses without generating any new questions. It uses only the questions already created by the teacher.

**First Attempt — Difficulty-ordered:**  
When a student takes a quiz for the first time, questions are presented in order of difficulty:
- Easy questions first (build confidence)
- Medium questions in the middle
- Hard questions last

No difficulty labels are shown to the student — the ordering happens silently.

**Retry — Weakness-weighted:**  
When a student retries after getting questions wrong:
- The system retrieves the IDs of questions they answered incorrectly in the previous attempt (stored in Firestore)
- It builds a new quiz with:
  - **60% of questions** from their weak areas (questions they got wrong)
  - **40% of questions** from other topics (reinforcement and new exposure)
- All questions are shuffled so the retry does not feel repetitive

An orange banner appears at the top of the retry quiz:  
*"Adaptive quiz — focused on your previous weak areas"*

**Gets smarter over time:**  
Each attempt saves new wrong question IDs. If a student keeps failing the same questions, those questions will continue appearing in every retry until they answer them correctly.

**No generation needed:**  
This system works entirely with already-generated questions. No AI calls are made during retry.

## 3. How Everything Connects

```
Teacher uploads PDF
        ↓
AI generates questions  →  Labels each as Easy / Medium / Hard
        ↓
Admin publishes quiz
        ↓
Student takes quiz (Easy → Medium → Hard order on first attempt)
        ↓
System records wrong question IDs + updates per-question attempt stats
        ↓
        ├──→ YouTube recommendations shown for weak topics
        │
        └──→ Retry quiz weighted 60% toward previously wrong questions
                        ↓
              Wrong IDs saved again → next retry adapts further
```

The ML pipeline runs separately (offline) and validates how accurately the AI labels questions compared to real student performance — feeding into the admin analytics dashboard.
