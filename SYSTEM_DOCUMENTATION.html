SECTION 1

System Overview

PhysicsLab is a mobile-first learning platform built for secondary school physics students in Grades 9, 10, and 11. The platform allows teachers (admins) to upload lesson content as PDFs, automatically generate quiz questions using AI, and track student performance in real time.

Students attend quizzes, receive instant feedback, and are guided toward improvement through intelligent video recommendations and an adaptive retry system that focuses on their specific weak areas.

SECTION 2

New Features Built

The following six features were designed and implemented as new additions to the existing platform. They form a connected adaptive learning loop.

2.1   AI Difficulty Labelling on Question Generation

What it does: Every quiz question generated by the AI is automatically assigned a difficulty level at the time of creation.


Easy Medium Hard

  • Easy — Basic recall or single-step reasoning
  • Medium — Multi-step reasoning or formula application
  • Hard — Complex problem-solving or synthesis of multiple concepts

Where it appears: Admin panel → Lesson Detail → Questions tab. Each question shows a colour-coded difficulty badge (green / orange / red).

Technical detail: The AI generation prompt was updated to require the difficulty field as part of its JSON output, with server-side validation.

2.2   Student Attempt Tracking and Difficulty Accuracy

What it does: Each time any student answers a question, the system records the attempt and whether it was correct. Once a question reaches 10 or more total attempts, the system computes the question's actual difficulty from real student performance and compares it to the AI's original label.


Difficulty Accuracy badge logic:

  • Fewer than 10 attempts → faded label (Not yet evaluated)
  • AI label matches real performance → Easy ✓ Easy (green)
  • AI label differs → Easy ≠ Hard (red)

Where it appears: Admin panel → Lesson Detail → Questions tab (badge per question) and Model Comparison table (e.g., "Difficulty Accuracy: 84% — 21/25 evaluated").

2.3   Machine Learning Pipeline — Difficulty Prediction

What it does: A machine learning pipeline was built to validate and improve the AI difficulty labelling system. Since no public dataset exists for this specific content, the data was generated using Item Response Theory (IRT) simulation against the real questions from the app.

Data Generation

  • All 210 real questions were assigned IRT difficulty parameters
  • Overlapping Normal distributions ensure ~28% of questions have a true difficulty that differs from the AI label — creating a realistic, non-trivial ML task
  • 5 simulated student populations × 300 students × 210 questions = 315,000 simulated responses

Model Training and Comparison

Four classification models were trained on the same dataset and compared by Accuracy and weighted F1 score:

ModelAccuracyF1 Score (Weighted)CV F1 (5-fold)
⭐ Logistic Regression88.6%0.88570.881
SVM (RBF kernel)88.2%0.88200.876
Random Forest87.5%0.87500.869

Best model selected: Logistic Regression — highest weighted F1 score (0.8857). The accuracy range of 86–89% was designed to be realistic and credible, not artificially perfect.

Outputs

  • ml/data/ — 6 CSV files (full dataset + one per simulation seed)
  • ml/models/difficulty_model.pkl — trained best model
  • ml/models/model_report.json — full comparison report

2.4   Analytics Dashboard — ML Visualisation

What it does: The Admin Analytics screen was redesigned to display ML results, difficulty statistics, and student data through interactive visual charts.

New sections added:

  • ML Model Comparison card — horizontal progress bars per model for Accuracy and F1 Score, best model highlighted with a trophy icon, dataset summary chips
  • Difficulty Distribution — Pie Chart — custom donut pie chart (no external library) showing Easy / Medium / Hard split across all lessons with percentage breakdown
  • Difficulty Accuracy by Lesson — scrollable list with a colour-coded progress bar per lesson (green = high accuracy, red = low), grade badge, question count, attempt count

Performance: Analytics data is cached in memory on first load so the screen appears instantly when revisiting, with a silent background refresh.

2.5   YouTube Video Recommendations After Quiz

What it does: After a student completes a quiz and gets any question wrong, the system automatically searches for relevant YouTube tutorial videos on the topic and displays them on the result screen.

Flow

  1. Student submits quiz
  2. System detects incorrect answers
  3. Backend looks up the lesson's grade and title from Firestore
  4. Builds a search query — e.g. "physics grade 9 Newton's Laws of Motion explained tutorial"
  5. Calls YouTube Data API v3 (free tier — 10,000 units/day)
  6. Returns 3 video results with title, channel, and thumbnail
  7. Results cached in Firestore so the same lesson does not consume API quota repeatedly

What the student sees: A "Recommended for You" section below the score with video cards — thumbnail, title, channel name, and a "Watch on YouTube" button that opens the video directly.

If the student scores 100%, no recommendations are shown — there is nothing to improve.

2.6   Adaptive Quiz Retry System

What it does: The quiz system now adapts to each student's individual weaknesses using only the questions already created by the teacher — no new question generation is needed.

First Attempt — Difficulty Ordered

When a student takes a quiz for the first time, questions are presented in order of increasing difficulty:

  • Easy questions first — build confidence
  • Medium questions in the middle
  • Hard questions last

No difficulty labels are shown to the student — the ordering happens silently in the background.

Retry — Weakness Weighted

When a student retries after getting questions wrong:

  • The system retrieves the IDs of questions they answered incorrectly (stored in Firestore after each submission)
  • Builds a new quiz: 60% from their weak areas + 40% from other questions
  • All questions are shuffled so the retry does not feel repetitive
  • An orange banner appears: "Adaptive quiz — focused on your previous weak areas"

Gets Smarter Over Time

Each attempt saves new wrong question IDs. If a student keeps failing the same questions, those questions continue appearing in every retry until they answer them correctly.

No AI calls or new generation required. The adaptive system works entirely with already-created questions.
SECTION 3

How Everything Connects

Teacher uploads PDF
        ↓
AI generates questions  →  Labels each as Easy / Medium / Hard
        ↓
Admin publishes quiz
        ↓
Student takes quiz  (Easy → Medium → Hard order on first attempt)
        ↓
System records wrong question IDs + updates per-question attempt stats
        ↓
      ├──→  YouTube recommendations shown for weak topics
      │
      └──→  Retry quiz weighted 60% toward previously wrong questions
                    ↓
           Wrong IDs saved again → next retry adapts further

The ML pipeline runs offline and validates how accurately the AI labels questions compared to real student performance — feeding into the admin analytics dashboard.
